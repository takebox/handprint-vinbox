# F18 — Tracks catalog

The Tracks page (Customize → Tracks, `/tracks`) lists every track the backend can
load: the built-in catalog bundled with the frontend plus personal and project
tracks reported by the Agent Server. A user searches and filters the cards
(filters are mirrored into the URL), opens a detail modal, switches tracks on or
off (saved to settings straight away, effective for new conversations only),
launches a track into chat, and reads how to add one with `/add-track`; after the
agent installs a track in a conversation, a banner offers a fresh conversation
that loads it.

Source: `src/routes/tracks-settings.tsx`, `src/components/features/tracks/`, `src/constants/tracks-docs.ts`, `src/hooks/use-track-enablement.ts`, `src/utils/track-enablement.ts`, `src/hooks/use-launch-track-in-chat.ts`, `src/api/tracks-service.ts`, `src/components/features/chat/track-install-restart-banner.tsx`, `src/utils/track-install-events.ts`.

## Sub-features

- `F18.page`: the page shows the title, description, the notice "Track changes apply to new conversations only.", an **Add track** button, a result count, the facet rail and the card grid. (Empty state "No tracks found." and loading skeletons are not reachable on a local backend.)
- `F18.search`: typing filters cards by name, description, content or trigger; after 300 ms the query is mirrored to `?q=` without a new history entry; the X clears it; no match shows "No tracks match your search."
- `F18.search-history`: browser Back/Forward put the matching query back into the search box.
- `F18.facets`: the desktop facet rail (State, Recommendation, Source, Category, Type) filters with per-row counts, writes canonical URL params, disables zero-count rows and offers **Clear filters**; deep links apply and unknown values are dropped.
- `F18.filters-modal`: below 768 px the rail is replaced by a **Filters** button with an active-count badge that opens the same facets in a modal with Clear filters and Close.
- `F18.card`: each card shows icon, name, source, a two-line description and pills; extra pills collapse into a `+N` popover; click, Enter or Space opens the detail modal.
- `F18.copy-source`: personal and project tracks (path sources) have a copy-path button on the card and in the modal that flips to "Copied to clipboard" for 2 s; built-in tracks (source `public`) have none.
- `F18.toggle`: the card's plus/check toggle switches a built-in track on or off; the choice survives a reload (`enabled_tracks` allow-list on a local backend).
- `F18.toggle-local`: switching a personal/project track off writes `disabled_tracks`; new conversations then do not load it, and do again once it is back on.
- `F18.toggle-error`: a failed save shows an error toast and nothing is persisted.
- `F18.track-in-chat`: an enabled track is loaded into new conversations and fires on its trigger; a disabled one is not.
- `F18.detail-modal`: the detail modal shows source, an Enabled/Disabled switch, description, pills and the read-only content; switching off disables **Use track**.
- `F18.detail-close`: the X, **Close**, Escape and a backdrop click close the detail modal.
- `F18.detail-pills`: the modal shows the full pill set (type, category, recommended, license, compatibility, version, triggers); pills that do not fit collapse into a `+N` button whose popover lists the rest without closing the modal.
- `F18.use-track`: **Use track** closes the modal, opens `/conversations` and pre-fills the composer with `/<track-name> `.
- `F18.add-track-modal`: **Add track** opens an instructions-only modal with a copyable `/add-track` example (which must point at an existing track), steps, URL formats, storage notes and a docs link; Close, X and Escape close it.
- `F18.install-banner`: after the agent installs a track with `/add-track`, the conversation shows "Installed to this workspace: …" with **Start new conversation with this track** (same workspace) and a dismiss X (session-only).
- `F18.phone`: at 390 px the page, cards and both modals fit without horizontal overflow; `/customize` shows a hub that links to Tracks and the header back button returns to it.
- `F18.cloud-link`: with a Cloud backend the Customize **Tracks** item opens the Cloud tracks page in a new tab instead of `/tracks` (blocked here).

## How to get to it (user POV)

- Sidebar **Customize** (`sidebar-tracks-link`, goes to `/customize`, which redirects to `/mcp` on desktop), then **Tracks** in the Customize navigation (`sidebar-extensions-/tracks`).
- Direct URL `/tracks`, with optional filters: `/tracks?q=docker&state=enabled&recommendation=recommended&source=project&category=agent-authoring&type=knowledge`.
- Command menu (`Control+k`/`Meta+k`): searching "Tracks" lists only **Customize** ("Browse tracks, plugins, and integrations."), which lands on `/mcp`; then click Tracks. There is no direct Tracks command.
- Phone: `/customize` shows the Customize hub (`extensions-mobile-hub`) with a Tracks row; on `/tracks` the header back button (`sidebar-mobile-back-button`) returns to the hub.
- Install banner: inside a conversation, after the agent ran `/add-track <GitHub URL>` (local backend only).
- Cloud: Customize → **Tracks** on a Cloud backend (external link).

## Gotchas

- `sidebar-tracks-link` is labelled **Customize** and lands on `/mcp` on desktop (`/customize` redirects); Tracks is one more click. Test ids embed the route: quote `'testid=sidebar-extensions-/tracks'`.
- A `browser click` on an **enabled** card toggle is lost when the pointer was not already over it: `pointerenter` swaps the checkmark icon for the X icon between mousedown and mouseup, so Chrome fires no click and no `PATCH /api/settings` goes out (#17941). `browser hover` the toggle first (or click twice). Turning a track on is not affected. Recorded as `fail` on `F18.toggle`.
- The card toggle and the facet rows are `role=switch`/`role=checkbox` buttons: read `aria-checked`. The modal switch is a hidden `<input>` (#17900): click the row text and read `.checked` with `browser eval`.
- Typing writes `?q=` with `replace` after a 300 ms debounce, so read `browser url` a second later; facet clicks push a history entry immediately.
- Facet counts are disjunctive: a row counts tracks matching the other groups' selections, so Disabled reads `0` (and is disabled) while Recommended is checked.
- Groups with fewer than two values are hidden (Source and Type on a fresh run) unless the URL selects one of their values.
- The run's `HOME` lives under `/tmp`, so a track in `~/.agents/tracks` is filed under Source **This project** (`source=project`), not **Personal**; with a real `/home/<user>` or `/Users/<user>` home it would be Personal.
